# Axes & Aces Monster Manual

A 146-page, 5E-compatible bestiary of all 168 monsters in the card game, built
entirely from the game's own art and data. Nothing here is published. The
files are ready to upload and the steps are in `UPLOAD.md`.

Nothing in this folder is reachable from the website: `netlify.toml` already
sends `/store/*` to a 404.

## Read these first

| File | What it is |
|---|---|
| `UPLOAD.md` | The numbered steps to put the book up for sale |
| `STORE.md` | The listing copy, the price, and which stores will take it |

## The short version of the store problem

**DriveThruRPG will not take this book**, and neither will Roll20 or DMs Guild
— one policy covers all three. Their Product Standards page says:

> Your content must be conceived and written by a human. We do not accept any
> product that includes text generated by AI tools.

Their banned-tools list names Claude and ChatGPT. The AI *art* would have been
fine — they explicitly allow it inside a rulebook, which is why the book format
was chosen — but the AI-written text rules it out, and no amount of editing
changes where the words came from.

**itch.io allows it** with its AI disclosure tag set, and that is where it
should go. Price $14.99.

| Output | Size | In git? |
|---|---|---|
| `dist/Axes-and-Aces-Monster-Manual.pdf` | ~93 MB | No |
| `dist/cover-itch.png` | ~1 MB | No |
| `build/panels/` (168 composited scenes) | ~71 MB | No |
| `build/roster.json`, `build/blocks.json` | ~400 KB | Yes |
| `foundry/axes-and-aces-monsters/` (code and data) | ~1 MB | Yes |
| `foundry/axes-and-aces-monsters/art/` | ~9 MB | No |

The large outputs stay out of git because they are regenerated in full from
the source: the PDF, the panels, and the module's copy of the 168 cut-outs,
which `art/` in the repo root already holds. The module's own code, manifest
and monster data are committed. Run the build once before zipping the module
and the art will be there.

## Rebuilding

From this folder:

```bash
python src/make.py
```

Six steps, about six minutes, most of it the two PDF passes. Pass `--force` to
redo the panels as well.

It only ever reads `dev/game.html` and `art/`. It does not write to either.

## How it is put together

| File | Job |
|---|---|
| `src/extract.py` | Pulls the roster out of `dev/game.html` — ten worlds, forty areas, 168 creatures with their balance numbers |
| `src/engine.py` | Turns those numbers into challenge ratings and stat block figures. The method is explained in the book's introduction |
| `src/families.py` | SRD trait wording and the creature families |
| `src/creatures*.py` | The 168 creatures: size, kind, speeds, traits, and what each one is |
| `src/statblock.py` | Measures and draws one stat block |
| `src/book.py` | Lays out the whole PDF, two passes so the contents can carry page numbers |
| `src/panels.py` | Composites each monster into its own scene |
| `src/foundry.py` | The free Foundry VTT module |
| `src/text.py` | The book's written content |

## Things worth knowing

**The art is small.** The monster cut-outs in `art/` are 420 pixels tall,
which is web size. They are composited into the 1280x714 scene backgrounds,
which carry the resolution, and enlarged at most 1.8x. The scenes print at
200–300 dpi; the creature layer is softer than that. It looks right in print
because the art is flat cel shading with heavy outlines, but it is not true
300 dpi artwork and the listing does not claim it is.

**The challenge ratings are derived, not playtested.** They are consistent
with each other, which is what matters for picking a monster, and the method
is written out in the introduction so a GM can judge it. That is stated in the
book rather than glossed over.

**The Foundry module has never been loaded into Foundry.** It is built to the
dnd5e schema and the JSON is valid, but nobody has run it. Install it once
before telling anyone it works.
