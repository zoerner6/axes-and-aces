# Axes & Aces Monster Manual

A 5E-compatible bestiary of all 168 monsters in the card game, built
entirely from the game's own art and data. Nothing here is published. The
files are ready to upload and the steps are in `UPLOAD.md`.

Nothing in this folder is reachable from the website: `netlify.toml` already
sends `/store/*` to a 404.

## Read these first

| File | What it is |
|---|---|
| `UPLOAD.md` | The numbered steps to put the book up for sale |
| `STORE.md` | The listing copy, the price, and which stores will take it |
| `AUDIT.md` | What was wrong with the first build and what was done about it |

## The short version of the store problem

**DriveThruRPG will not take this book**, and neither will Roll20 or DMs Guild
— one policy covers all three. Their Product Standards page says:

> Your content must be conceived and written by a human. We do not accept any
> product that includes text generated by AI tools.

Their banned-tools list names Claude and ChatGPT. The AI *art* would have been
fine — they explicitly allow it inside a rulebook, which is why the book format
was chosen — but the AI-written text rules it out, and no amount of editing
changes where the words came from.

**Two stores are open.** itch.io takes the PDF at $14.99 with its AI
disclosure tag set. Amazon KDP takes a 138-page paperback at $29.99, which
requires an AI-content disclosure at upload and allows the book on that
basis; print-ready interior and wraparound cover are both built. Foundry
VTT's package browser is closed to it for the same reason as DriveThruRPG,
so the free module installs from a link.

`STORE.md` has the print arithmetic. One thing not to get wrong: **KDP locks
the ink type to the ISBN once the book is published**, so standard versus
premium colour has to be settled from a proof beforehand.

The large outputs stay out of git because they are regenerated in full from
the source: the PDF, the panels, and the module's copy of the 168 cut-outs,
which `art/` in the repo root already holds. The module's own code, manifest
and monster data are committed. Run the build once before zipping the module
and the art will be there.

## Rebuilding

From this folder:

```bash
python src/make.py
```

Six steps, about six minutes, most of it the two PDF passes. Pass `--force` to
redo the panels as well.

It only ever reads `dev/game.html` and `art/`. It does not write to either.

## How it is put together

| File | Job |
|---|---|
| `src/extract.py` | Pulls the roster out of `dev/game.html` — ten worlds, forty areas, 168 creatures with their balance numbers |
| `src/engine.py` | Turns those numbers into challenge ratings and stat block figures. The method is explained in the book's introduction |
| `src/families.py` | SRD trait wording and the creature families |
| `src/creatures*.py` | The 168 creatures: size, kind, speeds, traits, and what each one is |
| `src/statblock.py` | Measures and draws one stat block |
| `src/book.py` | Lays out the whole PDF, two passes so the contents can carry page numbers |
| `src/panels.py` | Composites each monster into its own scene |
| `src/foundry.py` | The free Foundry VTT module |
| `src/legendary.py` | Legendary actions, lair actions and the nine spellcasters |
| `src/text.py` | The book's written content |
| `src/layoutcheck.py` | Finds rules drawn through text, overlapping text and margin breaches, on every page |
| `src/sheets.py` | Renders every page into contact sheets, for looking at |

## Checking a build

Measuring the text is not enough. The first print had the rule under every
section heading struck through the heading itself, on all 168 stat blocks,
and no amount of reading the extracted text would have shown it. From
`store/monstermanual/`:

```bash
python src/layoutcheck.py dist/Axes-and-Aces-Monster-Manual-KDP-interior.pdf --kdp
```

All three counts should be zero. Then look at the pages:

```bash
python src/sheets.py dist/Axes-and-Aces-Monster-Manual-KDP-interior.pdf build/preview
```

## Things worth knowing

**The art is small.** The monster cut-outs in `art/` are 420 pixels tall,
which is web size. They are composited into the 1280x714 scene backgrounds,
which carry the resolution, and enlarged at most 1.8x. The scenes print at
200–300 dpi; the creature layer is softer than that. It looks right in print
because the art is flat cel shading with heavy outlines, but it is not true
300 dpi artwork and the listing does not claim it is.

**Much of the art is cut off by its own canvas.** Measured across all 168:
every one touches an edge, and ten are cut by 60 pixels or more — the Bog Hag
loses 280 pixels across her bottom, the Ice Witch 253, the Lich 248. Those are
cutouts, so the alpha ends in a dead straight line, and dropped into a scene
that line reads as a printing fault rather than as art.

`src/panels.py` measures each one and deals with it: a cut bottom is run off
the bottom of the panel, where the panel border covers it and the creature
still reads as standing in the scene, and a cut top or side is feathered where
it is. Only the bottom is run off the frame. Doing the same to a cut top drags
the creature into a corner with its feet in mid-air — the Demon Sorcerer's cut
top is his raised flame, not his head. If you change the panel style, re-check
these; `build/edges.json` has the per-monster measurements.

**The challenge ratings are derived, not playtested.** They are consistent
with each other and they are checked against the Dungeon Master's Guide's own
figures for armor class, attack bonus and damage a round, so a rating here
buys the same thing it buys in any other book when you spend an XP budget.
Hit points are the exception: the DMG's low rows ask for fifty to seventy at
challenge 1/2, where published creatures carry fifteen to twenty-six, so that
column follows published creatures at the bottom and the table from challenge
13 up. `AUDIT.md` has the measurements and `src/engine.py` the tables. None of
it is playtested, and the introduction says so.

**The Foundry module has never been loaded into Foundry.** It is built to the
dnd5e schema and the JSON is valid, but nobody has run it. Install it once
before telling anyone it works.
